# Roadmap

Pizza Bot's roadmap is a set of areas to explore, not a release schedule or a
commitment to ship specific features. Concrete work is tracked in GitHub issues
and pull requests; this page stays intentionally short so it can describe
direction without becoming a second backlog.

## Principles

### Local-first means Pizza Bot can work where you do

It can use files, tools, and a browser on your computer. You shouldn't have to
wait for an official integration before automating a task.

### You should know where your data goes

Conversations and memory are stored on your machine by default. When Pizza Bot
sends data to a model provider, MCP server, or remote backend, it should be clear
what is being sent and why.

### Use the model that fits the job

Different tasks call for different models. Pizza Bot should let you choose the
provider and model that work for you instead of locking you into one option.

### We want people to use Pizza Bot because it helps

Success means people keep coming back because Pizza Bot saves them time and
works well, not because someone told them they have to use it.

### If Pizza Bot is missing something, you should be able to add it

Skills, plugins, and MCP servers let you adapt Pizza Bot to your own work. When
you build something useful, it should be easy to share with other people.

## What we're exploring

### Make skills and plugins easier to find

Finding an extension should be easier than tracking down a ZIP file. We want to
explore marketplace integration for browsing, installing, and updating skills
and plugins from Pizza Bot. Before installing anything, people should be able to
see who published it, what it can access, and what dependencies it brings.

## Proposing work

Open a GitHub issue with the repository's feature request template. Describe the
workflow, security boundary, and evidence that would make a proposal ready for
adoption.
